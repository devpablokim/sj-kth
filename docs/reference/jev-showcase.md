# JEV 쇼케이스(jev-showcase.vercel.app) 직접 사용 로그 — 2026-09-20

초대 코드로 로그인해 5개 데모(리뷰·스미싱·실시간·2048·워들)를 실제로 실행하고,
브라우저가 보낸 **jev 호출 93회의 요청/응답 JSON**을 가로채 정리한 기록입니다. 이 툴의 파이프라인·비용 표시·판정 로그 패널 설계의 근거 자료입니다.
(같은 폴더: `jev-showcase-samples.json` 데모별 대표 요청/응답, `jev-showcase-calls.csv` 호출별 지표. 사이트는 초대 전용이라 접속 코드와 전체 원본 캡처는 저장소에 넣지 않았습니다.)

## 1. 호출 방식 (우리 툴에 그대로 적용 가능한 부분)

- 브라우저 → 사이트 자체 서버 `POST /api/jev` → jev. **키는 서버에만** 있고 브라우저에는 노출되지 않음.
- 요청 형식: `{ tag, state, questions }`
  - `state` = 공유 컨텍스트 (예: `{"context":"네이버 영화 리뷰 감정 분류"}` 또는 `{"text":"…한 문장…"}`)
  - `questions` = 질문 ID → `{ type, instructions, criteria }`
  - **질문 type 3종**: `choice`(선택지 map), `score`(단계 배열), `noul`(참/거짓 확률. AI SDK의 `boolean`에 해당)
- 응답 형식: `{ model:"jev-1.13.0", answers, usage:{input_tokens,output_tokens}, _meta:{upstreamMs,tokens,krw,tag,attempt} }`
  - `choice` → `{choice, confidence, probabilities}` / `score` → `{score, confidence, legend, probabilities}` / `noul` → `{noul: 0.04}`
  - `confidence` 필드가 따로 옴 (AI SDK 타입에는 없음, probabilities 로 대체 가능)

## 2. 배치 전략 — 데모별로 다름

| 데모 | 한 호출에 담는 것 | 질문 수/호출 | 호출 수 |
|---|---|---|---|
| 리뷰 감정 | 리뷰 10건, 각각 별도 choice 질문 (instructions 에 리뷰 원문 삽입) | 10 | 30 (300건) |
| 스미싱 | 문자 8통 choice + 압박강도 score 1개 | 9 | 9 (72통) |
| 실시간 | 문장 1개를 `state.text` 에 두고 감정/긴급도/의도/욕설/위험 5개 질문 | 5 | 타이핑 멈출 때마다 |
| 2048 | 보드 상태를 `state` 에 두고 이번 수 + 다음 수 4방향 + 위험 = 6개 질문 | 6 | 수마다 |
| 워들 | 후보 단어 6개를 choice 로, 정답 임박 noul | 2 | 턴마다 |

핵심: **"항목 여러 개 × 질문 1개"면 항목을 질문에 박아 배치**, **"항목 1개 × 질문 여러 개"면 항목을 state 에 두고 질문만 나열**.
우리 툴은 포스트 1건에 질문 10개이므로 후자(포스트 = state)가 토큰상 유리함 — 포스트 본문을 질문마다 반복하지 않아도 됨.

## 3. 실측 지연·비용 (93회 호출)

| 데모 | 호출 | API 평균(upstreamMs) | p95 | 평균 입력 토큰 | 누적 ₩ | 브라우저 왕복 평균 |

| 워들 | 24 | 230ms | 282ms | 1,095 | ₩1.52 | 245ms |
| **합계** | **93** | | | **162,113 tok** | **₩9.40** | |

- 비용은 **입력 토큰 기준 ₩0.058 / 1k 토큰** (≈ $0.04 / 1M 토큰, 사이트 표시값 역산). 질문을 9~10개 묶어도 호출당 200~500ms.
- 리뷰 300건: 30.7초, 30회 호출, ₩2.1, 사람 라벨 일치율 90% (확신 ≥0.9 구간은 96%, 확신 <0.5 검토 대상 31건 10%).
- 스미싱 72통: 9회 호출, ₩1.4, 정답 일치율 100%, 평균 확신 .95.

## 4. 마케팅 문구를 실시간 데모에 직접 넣어본 결과

입력: `오늘 자정 마감! 직장인 90%가 선택한 집중 타이머, 지금 신청하면 첫 달 무료 — 댓글에 "타이머" 남기면 가이드 DM 드려요`

- 감정: 기쁨·만족 .45 / 불안·걱정 .36 / 중립 .19 (확신 .31 → "검토" 표시)
- 긴급도: 1.78 / 2 (매우 급함) — 마감·즉시 신청 문구를 정확히 잡음
- 의도: 요청·부탁 1.00 / 욕설 .02 / 위험 .01
- API 475ms · 1,007 tok · ₩0.06

→ 긴급성(urgency)·CTA 강도 같은 우리 질문에 jev 가 잘 반응한다는 근거.

## 5. UI 에서 가져올 만한 것

- 우측 고정 **판정 로그 패널**: 시각 · TAG · 한 줄 요약 · 왕복 ms · `API ms · tok · ₩`, **JSON 펼침** 토글로 요청/응답 원문 표시, 상단 지연 스파크라인 + 평균/p95 + 누적 호출/₩
- **확신도 구간 지표**: 확신 ≥0.9 구간 일치율 / 확신 <0.5 검토 건수 → "사람이 다시 봐야 할 몫"
- 틀린 건을 숨기지 않고 따로 모으는 리스트
